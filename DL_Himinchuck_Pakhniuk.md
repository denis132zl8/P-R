Тема: Відтворення та верифікація методу виявлення Out-of-Distribution (OOD) даних на основі теорії динамічних систем та показників Ляпунова

Актуальність теми. Проблема виявлення аномалій та даних, що не належать до навчального розподілу (Out-of-Distribution, OOD), є критичною для забезпечення надійності систем штучного інтелекту в реальних умовах. Традиційні нейронні мережі часто демонструють високу впевненість у хибних прогнозах на незнайомих даних. Сучасним перспективним підходом є розгляд глибоких нейронних мереж як неперервних динамічних систем (Neural ODE), де стійкість траєкторій (оцінена за допомогою показників Ляпунова) використовується для відділення відомих даних від невідомих.

Мета роботи: Незалежне відтворення та верифікація результатів наукової статті щодо використання спеціалізованих функцій втрат і теорії динамічних систем для ідентифікації OOD-даних.

Об'єкт дослідження: Процес класифікації та виявлення аномальних даних у глибоких нейронних мережах.

Предмет дослідження: Архітектура Continuous-depth networks (Neural ODE) та функції втрат, що базуються на оцінці показників Ляпунова (Jacobian regularization).

Методи дослідження: Математичне моделювання динамічних систем, оптимізація цільових функцій, емпіричний аналіз показників AUROC та FPR95.





# ТЕОРЕТИЧНІ ВІДОМОСТІ ТА АНАЛІЗ БАЗОВОЇ СТАТТІ

## 1.1. Основні висновки з базової статті (arXiv:2410.10744)

У статті досліджується новий підхід до OOD-детекції шляхом інтеграції цілеспрямованої функції втрат у нейронні звичайні диференціальні рівняння (Neural ODEs). Основні тези:

Динамічна сепарація: Мережа розглядається як динамічна система. Завдяки спеціальній функції втрат, система навчається формувати стабільні атрактори для In-Distribution (ID) даних та нестабільні траєкторії для OOD-даних.

Показники Ляпунова: Стабільність динамічної системи локально оцінюється через спектр матриці Якобі. Негативні власні значення (що відповідають від'ємним показникам Ляпунова) свідчать про стійкість до збурень, тоді як позитивні — про розбіжність траєкторій.

Регуляризація матриці Якобі: Замість прямого обчислення експонент Ляпунова (що є обчислювально важким), автори пропонують штрафувати діагональні та позадіагональні елементи матриці Якобі для керування динамікою.

Архітектура: Мережа складається з базового екстрактора ознак (ResNet50 від бібліотеки timm), ODE-блоку для моделювання динаміки та лінійного класифікатора.



## 2.2. Фрагменти коду, що відповідають за основну логіку

Фрагмент 1. Попереднє донавчання (Pre-tuning) базового екстрактора ознак.

Критичним етапом для коректної роботи методу є підготовка простору ознак. Для цього базовий екстрактор (ResNet) проходить етап попереднього навчання на цільовому датасеті з використанням тимчасового лінійного класифікатора. Це гарантує, що In-Distribution дані утворюють щільні кластери до початку обчислення експонент Ляпунова.

Python

# Файл: main.py (витяг)

def pretrain_model(model, train_loader, num_classes, epochs=5, lr=1e-4, device='cuda'):

print(f"--- Starting Pre-tuning for {epochs} epochs ---")

feature_dim = 2048 # для resnet50

classifier = nn.Linear(feature_dim, num_classes).to(device)

optimizer = torch.optim.Adam(list(model.parameters()) + list(classifier.parameters()), lr=lr)

criterion = nn.CrossEntropyLoss()



model.train()

for epoch in range(epochs):

for imgs, lbls in train_loader:

imgs, lbls = imgs.to(device), lbls.to(device)

optimizer.zero_grad()

features = model(imgs)

logits = classifier(features)

loss = criterion(logits, lbls)

loss.backward()

optimizer.step()

model.eval()

return model

Фрагмент 3. Енергетична функція втрат.

Для розділення потоків (ID та OOD) застосовується Margin Loss на основі енергії виходів мережі. Мережа штрафується, якщо енергія синтезованих даних опускається нижче заданого порогу margin_val.

Python

# Енергія чистих даних (ID)

energy_id = torch.logsumexp(outputs_id, dim=1)

# Енергія фейкових даних (OOD)

energy_ood = torch.logsumexp(out_fake, dim=1)



# Штрафуємо модель, якщо OOD енергія занадто висока (менша за -margin_val)

margin_val = -5.0

loss_ood = torch.mean(F.relu(energy_ood - margin_val))



# Комбінована функція втрат

loss = loss_id + 0.1 * loss_ood

loss.backward()



































# РЕЗУЛЬТАТИ ЕКСПЕРИМЕНТІВ ТА ЇХ АНАЛІЗ

## 3.1. Метрики оцінювання

Для оцінки якості детекції OOD використовувались наступні загальноприйняті метрики:

AUROC (Area Under the Receiver Operating Characteristic curve) — ймовірність того, що випадковий позитивний приклад отримає вищу оцінку, ніж випадковий негативний. Чим ближче до 1.0, тим краще.

FPR95 (False Positive Rate at 95% True Positive Rate) — частка помилково класифікованих OOD-даних як ID, коли система правильно розпізнає 95% ID-даних. Менше значення є кращим.

AUPR (Area Under the Precision-Recall curve) — площа під кривою точності-повноти.

## 3.2. Емпіричні результати

## 3.3. Аналіз складнощів та розбіжностей

Отримані результати демонструють значний прогрес, але підтверджують деякі фундаментальні виклики підходу:

Успішне вирішення проблеми базового виявлення (FPR95): Введення етапу попереднього донавчання екстрактора ознак кардинально покращило ситуацію. Показник AUROC досяг 94.6%, а FPR95 знизився до прийнятних 20.4%. Це доводить, що регуляризація Якобіану (оцінка стійкості Ляпунова) ефективно працює лише тоді, коли початковий простір ознак вже структурований.

Вразливість до атак (Adversarial Robustness): Незважаючи на чудові результати на чистих даних, при застосуванні атаки Projected Gradient Descent (PGD) якість OOD-детекції стрімко падає (AUROC знижується до 67.3%, а FPR95 зростає до 81.2%). Це підтверджує гіпотезу, що хоча показники Ляпунова формують стабільні атрактори для ID-даних, цілеспрямований змагальний шум здатен змістити траєкторію виводу за межі цих атракторів, обманюючи енергетичний детектор.

Обчислювальна складність: Швидкість обробки під час генерації змагальних прикладів через ODE-блок залишається низькою (~2.74 секунди на один батч, загальний час тестування понад 11 хвилин). Це пов'язано зі значними витратами на обчислення градієнтів через динамічну систему під час оптимізації PGD.
